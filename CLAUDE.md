# keep-together

Open-source (AGPL-3.0) UK fundraising CRM for small community groups and
charities: donor management, Direct Debit, painless HMRC Gift Aid.
Successor to `../ngo-go` (Django): same domain, rebuilt as a Rust api
with **one SQLite file per organisation** and a React SPA, on one Fly
machine per environment that nobody has to babysit.

Read `docs/architecture.md` before structural changes; the reasoning is
in `docs/decisions/`: **0024 is the stack decision** (it amends 0017, the
founding one, which still says which inherited ADRs apply). The CiviCRM
domain reference (data model, Gift Aid, GDPR) is `docs/research.md`: read
the relevant B-section before modelling any domain entity. Product
context: `docs/product-brief.md`. What ngo-go's code and tests had
already pinned down, and the checklist to re-prove it here:
`docs/inherited-from-ngo-go.md`. Before touching `server/`, read
`server/README.md`: crates, HTTP conventions, the write path,
migrations, jobs, `keep`.

## Non-negotiable domain rules

1. A Gift Aid declaration is a **dated chain, not a boolean** — eligibility
   = contribution date vs declaration windows.
2. Consent is an **immutable per-channel, per-purpose log**; current
   preferences are always **derived** from it.
3. Erasure = **anonymise, don't delete** — financial/tax history is
   preserved. Never cascade-delete from a contact.
4. The Gift Aid reclaim is a **real financial record**, not a custom field.
5. Transactional-vs-marketing **suppression is centralised** in `comms`;
   marketing opt-out never blocks transactional email.
6. **Domain code never mentions tenants.** The organisation's file is
   the scope: no `tenantId` column anywhere, and domain crates can't name
   or open another organisation's file.
7. Money is **`INTEGER` pence** — never `REAL`, never pounds; `bigint` in
   the SPA.

## Stack

Rust (axum, rusqlite with bundled SQLite, tokio) in `server/` ·
`platform.db` plus `orgs/<tenant-id>.db` · Litestream to S3 and hourly
snapshots to a locked bucket · Fly.io London · Vite + React 19 +
TanStack Router (file-based) and Query + Tailwind v4 + shadcn/ui, built
as a static SPA the api serves from the same origin · server-sent events
for liveness · pnpm · cargo test, vitest, Playwright (QC).

## Layout

| Path | Owns |
|---|---|
| `server/crates/store` | `platform.db` and the org files: pragmas, one writer + reader pool per file, the handle LRU, boot migration, event channels |
| `server/crates/contracts` | the **only write path**: `transact`, `Contract`, `execute`, revisions, command groups, restore through upcasters, child-row reconcile, events |
| `server/crates/{contacts,sources,giving,giftaid,comms}` | domain modules: contracts, pure rules, reads. Depend on `contracts` (and each other's public functions), never on `store`, `platform`, `auth` or `api` (a test reads their manifests) |
| `server/crates/platform`, `auth` | control plane (preferences, settings, memberships) and staff auth, in `platform.db` |
| `server/crates/api` | the axum app: routes, `Tenant`, SSE, `/boot`, jobs, `/healthz`, backups; `schema.rs` is the org migration list. Commands that span modules live here, in one transaction |
| `server/crates/cli`, `seed` | `keep` (the operator CLI) and the seeded worlds (`riverside`, `perf`) |
| `src/routes/` | file-based routes; `src/components/ui/` is shadcn (generated, edit freely) |
| `src/lib/data/` | the SPA's data layer: TanStack Query over the api, the SSE client, the wire adapters; `rust-types/` is generated by `cargo test` (ts-rs) |
| `src/lib/domain/` | the shapes the pages render and the pure rules shared with the server (warnings, Gift Aid coverage, check digits, limits): keep them in step with the Rust they name |
| `qc/` | the Playwright QC suite and its budgets (ADR 0018) |
| `scripts/` | `dev.mjs` (`pnpm dev`), `qc.mjs`, `fly/`, `aws/`, `ops/`, `preview/`, `qc-nightly/` |
| `docs/` | architecture, ops, ADRs, domain research, product brief |

## Commands — pnpm scripts first

`pnpm dev` (api rebuilt on save + Vite with HMR, shared on the tailnet;
`--local` for loopback; README "Dev loop") · `pnpm dev:reset` (wipe and
reseed riverside) · `pnpm check` (clippy + cargo test, then typecheck +
lint + vitest: what CI runs) · `pnpm qc` (the QC suite; `qc/README.md`) ·
`pnpm build`. From `server/`: `cargo test`, `cargo clippy --all-targets
-- -D warnings`, `cargo run -p cli --bin keep -- …`. Agents' SQL goes
through `keep sql <slug> "<select…>"`: read-only by construction.

## Conventions

- **Every domain write is a contract**, only through
  `contracts::transact` → `execute` (sealed: an `OrgTx` has no write
  method; `compile_fail` doctests prove it), each command atomic under
  its own savepoint. Handlers are pure state application; side effects
  happen after the commit (events, jobs). `ctx.tx.read()` is refused
  writes at runtime (`query_only`), not at compile time, so domain crates
  must not contain `query_only`, `authorizer(`,
  `unchecked_transaction`, or SQL literals starting with
  `COMMIT`/`BEGIN`/`ROLLBACK`/`SAVEPOINT`/`RELEASE`/`ATTACH`/`PRAGMA`/`END`
  (`server/crates/api/tests/schema.rs` greps for them).
- **Contracts partition their entity**: no two contracts touch the same
  fields; each has its own `INTEGER` counter on the root row. Operations
  over several slices run several contracts in one transaction under a
  named command group. Child rows live inside the root's contract payload
  and **carry ids** (ADR 0014): reconciled by key, identity fields (email
  address, phone number) immutable per key — change = remove + add;
  addresses fully editable in place. Handlers preserve system-owned
  fields no payload carries across every save, reconcile and restore.
- **Derived rows** (the contact search projection) are written only by a
  contract's `project` hook, in the same transaction, and only to the
  tables its `PROJECTIONS` names: no counter, no revisions.
- Update contracts take `expected: <counter>`; on mismatch the api
  answers `409 {kind:"stale", contract, counter, current}` so the form
  merges and retries. Different sections never falsely conflict.
- **Revisions** store the payload as JSON + contract name + declared
  version. Changing a contract's fields = bump its version + register an
  upcaster; restore chains upcasters (ADR 0013).
- **Schema**: append a step to `api::schema::org_migrations()` and its
  fixture to `FIXTURES` in `server/crates/api/tests/schema.rs`. One
  transactional step per change; files migrate at boot, copy first, fail
  closed. Never edit a shipped step. No `REAL` column anywhere (a schema
  test).
- **Validation has two tiers** (ADR 0015): `422 invalid` only for
  unstorable or invariant-breaking data (an email is any string); "probably
  wrong but storable" saves and is flagged by warnings, computed by the
  server in reads and by the same rules in `src/lib/domain/` as the user
  types.
- **Tenancy is the file** (rule 6): a request reaches `/api/t/{slug}/…`,
  the session and membership resolve the slug to that one file, and
  handlers get a `Tenant` (`read`/`write`). A new table goes in the org
  schema, with no tenant column.
- **Every route** gets an isolation test (two orgs: B never sees A; A's
  ids under B's slug are 404). Client-chosen ids are 32 lower-case hex.
- **Live updates**: each committed contract is an SSE event
  (`/api/t/{slug}/events`, ids only); clients refetch. Gifts and other
  financial records are never optimistic.
- **Jobs**: register on `api::jobs`; loop orgs with `each_org`, one file
  at a time. Reports and lists are indexed queries over one org's file.
- **Local only**: each checkout runs its api on its own `KEEP_PORT`
  (8787 + n; `pnpm dev` picks it) with data in `server/data/`; agents
  make no cloud deployments. `KEEP_DEV_AUTH=1` is no auth and only works
  on a loopback bind; `pnpm dev` never sets it.
- **Generated and committed**: `src/lib/data/rust-types/` (`cargo test`)
  and `src/routeTree.gen.ts` (`pnpm generate-routes`, or Vite); never
  edit by hand. CI fails if the committed TS types differ.
- **Tests**: every rule gets a named Rust (or dom) test; `cargo test`,
  `cargo clippy --all-targets -- -D warnings` (from `server/`) and `pnpm
  check`. QC flows (`pnpm qc`) for anything that changes a page's timing.
- Cross-module calls go through a crate's public functions, never its
  internals. Comments citing `convex/…` name the Convex code a piece was
  ported from (tag `convex-final`).
