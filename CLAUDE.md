# keep-together

Open-source (AGPL-3.0) UK fundraising CRM for small community groups and
charities: donor management, Direct Debit, painless HMRC Gift Aid.
Successor experiment to `../ngo-go` (Django): same domain, rebuilt as the
cheapest *managed* stack — nobody maintains a server.

Read `docs/architecture.md` before structural changes; the reasoning is
in `docs/decisions/` — **0017 is the founding decision**, and says which
inherited ADRs still apply. The CiviCRM domain reference (data model,
Gift Aid, GDPR) is `docs/research.md` — read the relevant B-section
before modelling any domain entity. Product context: `docs/product-brief.md`.
What ngo-go's code and tests had already pinned down, and the checklist
to re-prove it here: `docs/inherited-from-ngo-go.md`.
Before touching `convex/`, read `convex/_generated/ai/guidelines.md`
(Convex's own API rules, regenerated by `pnpm convex`) — see "Convex
guidance" at the end for how it ranks against this file.

## Non-negotiable domain rules

1. A Gift Aid declaration is a **dated chain, not a boolean** — eligibility
   = contribution date vs declaration windows.
2. Consent is an **immutable per-channel, per-purpose log**; current
   preferences are always **derived** from it.
3. Erasure = **anonymise, don't delete** — financial/tax history is
   preserved. Never cascade-delete from a contact.
4. The Gift Aid reclaim is a **real financial record**, not a custom field.
5. Transactional-vs-marketing **suppression is centralised** in `comms`;
   marketing opt-out never blocks transactional email.
6. **Domain code never mentions tenants.** Tenancy is enforced by the
   scoped function constructors (below), never by a filter a handler
   remembers to write.
7. Money is integer pence (`v.int64()`) — never float, never pounds.

## Migration to Rust (in progress)

keep-together is moving off Convex to Rust (axum + rusqlite) with **one
SQLite file per organisation** (`factory/plans/migration-rust.sv`; ADR
0024). Until cutover:

- **Convex is frozen**: fixes only. New and ported work goes in `rs/`;
  `convex/` is read-only reference for the port. The Convex sections of
  this file stay true for `convex/` and go at cutover.
- Read `rs/README.md` first: crates, HTTP conventions, the write path,
  migrations, jobs, `keep`.
- **Writes**: only through `contracts::transact` → `execute` (sealed: an
  `OrgTx` has no write method; `trybuild` proves it). Handlers are pure
  state application; derived rows only in a contract's `project` hook.
- **Tenancy is the file** (rule 6): no `tenantId` columns, no scoped
  constructors. Domain crates depend on `contracts`, never on `store`,
  `platform`, `auth` or `api` (a test reads their manifests). Commands
  that span modules live in `api`, in one transaction.
- **Money** is `INTEGER` pence; no `REAL` column anywhere (a schema test).
- **Schema**: append a step to `api::schema::org_migrations()` and its
  fixture to `FIXTURES` in `rs/crates/api/tests/schema.rs`. One
  transactional step per change; files migrate at boot, copy first, fail
  closed. Never edit a shipped step.
- **Every route** gets an isolation test (two orgs: B never sees A; A's ids
  under B's slug are 404). Client-chosen ids are 32 lower-case hex.
- **Live updates**: each committed contract is an SSE event
  (`/api/t/{slug}/events`, ids only); clients refetch. Gifts are never
  optimistic.
- **Jobs**: register on `api::jobs`; loop orgs with `each_org`, one file
  at a time.
- **Local only**: each worktree runs its api on its own `KEEP_PORT` (8787 +
  n) with data in `rs/data/`; no cloud deployments, no Convex deploys.
  `KEEP_DEV_AUTH=1` is no auth and only works on a loopback bind.
- **Tests**: port every Convex test whose rule still holds as a named Rust
  (or dom) test; the report carries a parity table. `cargo test`, `cargo
  clippy --all-targets -- -D warnings` (from `rs/`) and `pnpm check`.
- Agents' SQL goes through `keep sql <slug> "<select…>"`: read-only by
  construction.

## Stack

Convex (all backend state + compute) · Vite + React 19 + TanStack Router
(file-based) + Tailwind v4 + shadcn/ui, built as a static SPA · Convex
Auth (email + password) · pnpm · vitest + `convex-test`. Static hosting is
interchangeable (GitHub Pages / local build over Tailscale); never depend
on where the SPA is served from. No SSR, no Node server of our own.

## Layout

| Path | Owns |
|---|---|
| `convex/lib/appSchema.ts` | every app table; all domain tables have `tenantId` and tenantId-first indexes. `convex/schema.ts` composes it with Convex Auth's `authTables` |
| `convex/lib/tenancy.ts` | `tenantQuery` / `tenantMutation` / `tenantAction` (+ `internal*`) — the only way to declare domain functions. Handlers get a **scoped db**: inserts stamped, every `withIndex` range starts *after* `tenantId`, no unindexed `query()` |
| `convex/lib/contracts.ts` | `executeContract`: counter check, pure apply, revision append |
| `convex/platform/` | control plane: tenants, memberships, settings, routing, billing. **Only place raw `query`/`mutation`/`action` may be imported** |
| `convex/{contacts,giving,giftaid,consent,comms,sources}/` | domain modules (boundaries in docs/architecture.md) |
| `convex/auth.ts`, `auth.config.ts`, `http.ts` | Convex Auth + HTTP routes (webhooks register here) |
| `src/routes/` | file-based routes; `src/components/ui/` is shadcn (generated, edit freely) |
| `src/lib/` | Convex client + auth provider, tenant resolution from hostname |
| `docs/` | architecture, ADRs, domain research, product brief |

## Conventions

- **Every domain write is a contract**: a `tenantMutation` whose args
  validator is the full state of its slice, run through `executeContract`
  — never `ctx.db.insert/patch/replace` on a domain table from anywhere
  else. Handlers are pure state application; side effects go through
  `ctx.scheduler` (fires only on commit) or an action.
- **Contracts partition their entity**: no two contracts touch the same
  fields; each has its own integer counter field on the root document.
  Multi-slice operations are *actions* running several contracts in one
  mutation under a named command group. Child rows live inside the
  root's contract payload and **carry ids** (ADR 0014): reconciled by id,
  identity fields (email address, phone number) immutable per id — change
  = remove + add; addresses fully editable in place. Handlers preserve
  system-owned fields no payload carries (e.g. a source code's `used`)
  across every save, reconcile and restore.
- **Derived projections** (`contactSearch`) are the one exception to
  "writes go through contracts": rebuilt from the root's current state by
  the contract's `project` hook inside the same transaction, never
  written anywhere else (bar their backfill), no counter, no revisions.
- Update contracts take `expected: <counter>`; on mismatch throw
  `ConvexError({ kind: "stale", current })` so the form can merge and
  retry. Different sections never falsely conflict.
- **Revisions** store the payload as `v.any()` + contract name + declared
  version. Changing a contract's fields = bump its version + register an
  upcaster; restore chains upcasters (ADR 0013 / 0017).
- **Schema changes are two-phase** (Convex validates existing documents
  on deploy): loosen → deploy → backfill via migrations component →
  tighten → deploy. Never ship a tightening with the loosening.
- **Validation has two tiers** (ADR 0015): validators block only
  unstorable / invariant-breaking data (email is `v.string()`, not a
  format check); "probably wrong but storable" saves and is flagged by an
  entity-level `warnings(entity)` function shared by backend and UI.
- **Tenancy is structural**: new table ⇒ `tenantId` + tenantId-first
  indexes (the schema test fails otherwise); new function ⇒ scoped
  constructor; new cron ⇒ fan out one job per tenant via Workpool; new
  per-tenant secret ⇒ `tenantSettings` (encrypted), never an env var.
  Every test fixture has two tenants and asserts isolation.
- **Dedicated instances run the same multi-tenant code.** Customisation
  for a client is a different bundle deployed to their deployment, never a
  per-tenant flag in shared code.
- Reports and lists are indexed queries or in-memory passes over one
  tenant's data; never a cross-tenant scan in one function (32k-document
  limit). Big jobs are paginated actions.
- **Deployments that exchange tenants must share lineage**: Convex ids
  encode a per-deployment table number, so a target deployment is born
  from a snapshot import (`import --replace-all`) *before* any schema
  push, and all deployments take schema changes in the same order
  (`docs/spikes/01-export-import.md`).
- Dev instances: `pnpm dev:instance <name>` (creates `dev/<name>` in the
  EU, sets auth keys, pushes); `platform/devSeed:demoTenant` seeds one.
  Test fixtures live in `test/` — anything under `convex/` is pushed.
- Cross-module imports go through a module's public functions, never its
  internals. Domain logic lives in plain TypeScript modules with the
  Convex handler as a thin wrapper — that is the portability boundary.
- `convex/_generated/` and `src/routeTree.gen.ts` are generated **and
  committed** (typechecking needs them); `pnpm convex` / `pnpm
  generate-routes` regenerate them — never edit by hand.

## Convex guidance

`pnpm convex` maintains the block below, `convex/_generated/ai/guidelines.md`,
the Convex skills in `.claude/skills/convex-*` (mirrored in `.agents/`,
pinned by `skills-lock.json`) and the same block in `AGENTS.md`. Leave the
markers alone so it can update them. Precedence when they disagree with
this file:

- **Convex API mechanics** (validators, pagination, index usage, scheduler,
  HTTP actions, runtime limits, Node vs Convex runtime): the guidelines
  win — they track the installed Convex version.
- **Project rules** win over the guidelines' defaults. Specifically: the
  guidelines say to register functions with `query`/`mutation`/`action`
  from `_generated/server`; here that is allowed **only under
  `convex/platform/`** — everywhere else use the scoped constructors in
  `convex/lib/tenancy.ts`. Likewise every domain write goes through
  `executeContract`, every domain table carries `tenantId`, and money is
  `v.int64()` pence, regardless of what a generic example shows.
- The Convex skills (`/convex-test`, `/convex-migrate`, `/convex-auth`,
  `/convex-reviewer` …) are useful; when one scaffolds code, re-apply the
  conventions above before keeping it.
